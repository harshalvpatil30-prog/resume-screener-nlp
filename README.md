# Candidate Screening & Resume Parser

An NLP pipeline that reads resumes (PDF/DOCX), extracts skills, compares each candidate with a job description using a Hugging Face transformer, and ranks candidates with an explainable score. Includes a Streamlit web app.

> **Note:** All resumes in this repo are **synthetic** (generated by `generate_resumes.py`). No real candidate data is used.

## How it works

```
Resume (PDF/DOCX) -> Extract & clean text -> Split into sections
   -> Extract skills (spaCy) -> Section-aware skill credit
   -> Semantic similarity to job description (Sentence-Transformers)
   -> Weighted score (0-100) -> Ranked list (CSV / Streamlit)
```

| Stage | Method | Library |
|-------|--------|---------|
| Text extraction | Read and clean PDF/DOCX, repair hyphenated line breaks | pdfplumber, python-docx |
| Section detection | Rule-based heading detection (Skills, Experience, Projects...) | Python |
| Skill extraction | Dictionary phrase matching + synonym map (e.g. "natural language processing" -> "nlp") | spaCy PhraseMatcher |
| Section weighting | Skill used in Experience/Projects = 1.0 credit, only listed = 0.6 | Python |
| Semantic matching | Resume chunks vs job description, cosine similarity (`all-MiniLM-L6-v2`) | sentence-transformers |
| Scoring | `100 x (0.40 x required + 0.15 x preferred + 0.45 x semantic)` | Python |
| Interface | Upload resumes, paste JD, view matched/missing skills, download CSV | Streamlit |

**Why two signals?** Keyword matching misses meaning ("ML" vs "machine learning"). Embeddings capture meaning but can miss exact required skills. The score combines both and shows matched and missing skills, so a recruiter can see why a candidate ranked where they did.

## Results

Evaluated on **30 synthetic resumes** (10 Good, 10 Maybe, 10 Poor) labeled in `data/labels.csv`, ranked against one AI/ML Engineer job description.

| Method | Precision@10 | Recall@10 | Spearman |
|--------|-------------|-----------|----------|
| Keyword-only baseline | 0.93 | 0.93 | 0.90 |
| Hybrid (skills + transformer), before synonym fix | 0.90 | 0.90 | 0.88 |
| Hybrid, after synonym fix | 1.00 | 1.00 | 0.90 |
| Hybrid + section weighting | 1.00 | 1.00 | 0.93 |

- **Error analysis:** a good candidate who wrote "natural language processing" instead of "NLP" was ranked #12. Adding a synonym map fixed it.
- **Keyword-stuffed resume:** a Sales Associate listing every required skill but with no relevant experience ranked #12 with the plain score and #18 of 30 with section weighting.
- Section weighting did not change Precision@10 (already at its ceiling); it improved overall ordering and separation.

### Time saved (estimate)

- **Measured:** the tool processed 30 resumes in **36.1 seconds**, including model loading (CPU).
- **Assumed:** recruiters self-report spending about 4-5 minutes per resume (TheLadders eye-tracking study, 2012); a human still reviews the shortlist at the same pace.
- **Estimated reduction:** about **66%** if the recruiter reads the top 10 of 30, and about **83%** if they read the top 5. The saving grows with the number of applicants, since only the shortlist is read.

Run `python estimate_time_saved.py` to reproduce the table. This is a modelled estimate, not a controlled time study.

## Limitations

- **Small, synthetic test set.** I wrote both the resumes and the labels, and fixed the synonym error after seeing it fail on the same data, so scores are optimistic. Real resumes (messy layouts, scanned PDFs, multiple columns) are harder.
- **Dictionary-based skills.** The tool only finds skills in `skills_list.txt` plus the synonym map. Unseen skills are missed.
- **Heading detection is rule-based.** Unusual headings may be missed; the tool then falls back to full credit for all skills.
- **Section weighting has a trade-off.** Real candidates who only list a skill (for example Git) lose some credit.
- **Time saving is an estimate**, based on published recruiter review times and a measured tool runtime.
- **Bias.** The tool is a screening aid and not a hiring decision-maker. A human should review every shortlist. Names, photos and other personal details are not used in scoring, but fairness has not been formally audited.
